# DB2UI Studio — no-code конструктор интерфейсов для PostgreSQL

DB2UI Studio — небольшое **десктопное приложение** для Windows, которое
позволяет **без знания программирования** подключиться к базе PostgreSQL,
увидеть её таблицы и собрать интерфейс: формы, кнопки, поля ввода,
выпадающие списки, изображения и таблицы с данными.

**Стек:** Python, Flask, pywebview (WebView2), psycopg2, PostgreSQL,
HTML/CSS/JavaScript.

---

## Что умеет приложение

- **Подключение к одной конкретной базе PostgreSQL.** Список баз и схем
  не показывается: вы вводите параметры подключения и работаете с одной
  базой. Новая база при необходимости создаётся из редактора.
- **Вкладки** — «Конструктор», «Авторизация» и «Функции и триггеры».
  Внутри конструктора открытые формы и системная вкладка
  **«Таблицы и связи»** находятся в одной полосе над холстом.
- **Палитра элементов** — форма-экран, текст, кнопка, поле ввода,
  выпадающий список, изображение, таблица, свободная панель и SQL-запрос.
- **Перетаскивание** — элементы и таблицы из базы перетаскиваются внутрь
  экрана «Форма» или в панель. Элементы можно двигать и менять размеры
  прямо на холсте, а панели свободно растягиваются.
- **Экран и рабочее пространство** — точечный холст служит только
  рабочим пространством. Приложение показывает один экран «Форма»;
  панели внутри него меняют размер вместе с содержимым.
- **Несколько форм** — дерево форм справа: создание, переименование,
  удаление и выбор стартовой формы. Каждая форма — отдельный экран
  со своим размером.
- **Свойства** — панель справа показывает свойства выбранного элемента:
  название, координаты, размеры, цвет, привязка к таблице и колонке,
  переход на другую форму и другие настройки.
- **ER-диаграмма** — вкладка «Таблицы и связи» показывает таблицы
  карточками: их можно перетаскивать, а связи создаются кнопкой **↗**
  у колонки. Ошибки показываются понятными сообщениями.
- **Редактор таблиц** — создание и удаление таблиц, добавление и удаление
  колонок, первичные ключи, уникальность, значения по умолчанию и внешние
  ключи. Создание новой базы данных доступно здесь же.
- **Авторизация без кода** — вход в предпросмотр по логину и паролю
  из таблицы вашей базы, регистрация новых пользователей и мастер
  создания таблицы пользователей с администратором.
- **Функции, процедуры и триггеры** — отдельная вкладка для создания
  серверных объектов PostgreSQL: готовые шаблоны, редактор SQL,
  загрузка существующего определения и удаление по OID.
- **Предпросмотр** — кнопка «Предпросмотр» открывает собранный интерфейс
  в окне точного размера формы. В нём работают переходы между формами,
  таблицы с данными, добавление, изменение и удаление записей
  (если у таблицы есть первичный ключ), вход, регистрация и выход.
- **Готовое приложение одним `.exe`** — файл, который открывается двойным
  кликом на другом компьютере и работает с живой базой PostgreSQL: формы,
  таблицы, добавление и изменение записей, SQL и вход. Python и зависимости
  на компьютере не нужны.
- **Десктопная версия** — один `DB2UI Studio.exe` и обычный установщик
  с ярлыками. Приложение открывается в собственном окне, браузер
  и командная строка не нужны.
- **Редактирование как в графическом редакторе** — двойной клик по тексту
  или кнопке, копирование Ctrl+C / Ctrl+V, выделение рамкой, откат
  и повтор Ctrl+Z / Ctrl+Y.
- **Выравнивание** — магнит к сетке и краям других элементов,
  направляющие, выравнивание группы, распределение по горизонтали
  и вертикали и равные промежутки в пикселях.
- **Автосохранение и файлы проектов** — проект сохраняется в папку
  `projects` автоматически; его можно скачать в файл `.db2ui.json`,
  загрузить обратно и хранить несколько версий в библиотеке.

## Быстрый запуск (Windows)

### Готовый установщик

1. Запустите **`DB2UI-Studio-Setup-1.3.0.exe`**. Права администратора
   не требуются: программа ставится в профиль пользователя.
2. После установки откройте **DB2UI Studio** из меню «Пуск» или с рабочего
   стола — ярлык создаётся установщиком.
3. На стартовом экране выберите сохранённый проект из списка — приложение
   подключится к базе сразу, без ввода пароля. Пароль сохраняется один раз
   в зашифрованном виде (Windows DPAPI) для вашей учётной записи Windows.
4. Или нажмите **«＋ Новый проект»** (создаст пустой интерфейс) и заполните:
   - **Название проекта** — по умолчанию совпадает с именем базы;
   - **Сервер** — например, `localhost`;
   - **База данных** — например, `postgres` или своя база;
   - **Пользователь** — например, `postgres`;
   - **Пароль** — ваш пароль PostgreSQL.
5. Нажмите **«Подключиться»**.

Приложение работает в собственном окне — браузер и консоль не нужны.
Порт PostgreSQL по умолчанию — `5432`; другой можно указать в разделе
**«Дополнительно»**.

Проекты, настройки и ключ сессий хранятся в
`%LOCALAPPDATA%\DB2UI Studio`. При удалении программы эта папка
не удаляется, поэтому проекты остаются на месте.

Для окна используется Microsoft Edge WebView2. На Windows 10 и 11 он
обычно уже установлен; если нет — установщик покажет ссылку на
бесплатный WebView2 Runtime. Без него приложение всё равно запустится,
но откроется в браузере.

### Запуск из исходников

1. Установите Python 3.10 или новее и PostgreSQL.
2. Убедитесь, что PostgreSQL запущен.
3. Дважды щёлкните **`run.bat`** — создастся `.venv`, установятся
   зависимости и откроется окно DB2UI Studio.
4. Для запуска в браузере (режим разработки) используйте **`run-web.bat`**.

### Запуск вручную

```powershell
cd DB2UI_Studio
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe desktop.py
```

Остановить приложение: закрыть окно приложения.
Отключиться от базы: кнопка **«Отключиться»** в верхней панели.

## Сборка десктопной версии

Нужен только Python: PyInstaller и Inno Setup ставятся скриптом.

```powershell
# один exe, без установщика
.\build-desktop.ps1 -SkipInstaller

# exe + установщик; при необходимости поставить Inno Setup через winget
.\build-desktop.ps1 -InstallInno
```

Результат:

- `dist\DB2UI Studio.exe` — автономный файл приложения;
- `dist\installer\DB2UI-Studio-Setup-<версия>.exe` — установщик
  с ярлыками и деинсталлятором.

Версию можно задать явно: `.\build-desktop.ps1 -Version 1.3.0`.
Скрипт собирает иконку, exe и установщик; повторная сборка не требует
установленного Python на компьютере пользователя.

## Как собрать интерфейс

1. **Подключитесь к базе.** После подключения слева появятся элементы
   и список таблиц вашей базы, а сверху — вкладки форм.
2. **Перетащите элемент** из левой палитры на холст. Можно просто нажать
   на элемент — он добавится в текущую форму.
3. **Перетащите таблицу** из списка «Таблицы БД» — на холсте появится
   таблица с привязкой к ней.
4. **Выделите элемент** на холсте. Справа откроется панель свойств:
   название, размеры, привязка, цвет, действие кнопки и т. д.
5. **Создайте формы** кнопкой `+` над холстом или в разделе «Формы».
   В свойствах кнопки выберите действие «Перейти на форму» и нужную форму.
6. **Настройте макет формы** в её свойствах: свободный режим или сетку
   с нужным числом строк, столбцов и отступом.
7. **Проверьте результат** кнопкой «Предпросмотр». В предпросмотре
   доступны реальные данные из базы.

### Типы элементов

| Элемент | Для чего нужен |
|---|---|
| **Форма** | Экран приложения. Один корневой элемент на форму: вокруг него точечный холст-рабочее пространство, а в предпросмотре показывается только он. Размер экрана меняется маркером, содержимое масштабируется. |
| **Текст** | Заголовок, подпись, пояснение. Настраиваются размер, цвет, начертание и выравнивание. |
| **Кнопка** | Переход на форму, возврат на главную, вход, регистрация, обновление таблиц, добавление записи из полей или выход из учётной записи. |
| **Поле ввода** | Привязывается к таблице и колонке. Используется вместе с кнопкой «Добавить запись из полей». |
| **Выпадающий список** | Combobox, привязанный к колонке. Если колонка ссылается на другую таблицу, показывает понятные названия (например, роли вместо 1/2/3). |
| **Изображение** | Картинка по ссылке или файл с компьютера. Настраиваются вписывание, скругление и подпись alt. |
| **Таблица** | Показывает строки выбранной таблицы. В предпросмотре можно добавлять, изменять и удалять записи. |
| **Панель** | Свободный контейнер, как `Panel` в WinForms. Меняет размер маркером, может содержать любые элементы и другие панели; содержимое масштабируется вместе с ней. |
| **SQL-запрос** | Выполняет обычный `SELECT` (или `WITH`) и показывает результат таблицей. Только чтение, без изменения данных. |

### Привязка и переходы

- **Таблица** привязывается к таблице базы в свойствах. Настраиваются
  количество строк и разрешения на добавление, изменение и удаление.
- **Поле ввода и выпадающий список** привязываются к таблице и её колонке.
- **Кнопка** может:
  - открыть другую форму;
  - вернуться на стартовую форму;
  - обновить данные таблиц;
  - добавить запись из полей текущей формы;
  - войти в предпросмотр или зарегистрировать пользователя;
  - выйти из учётной записи приложения.
- Для добавления записи кнопке нужно указать таблицу, а полям — колонки
  этой же таблицы.
- **SQL-запрос** — это отдельный элемент с читающим запросом
  (`SELECT` / `WITH`). Сервер выполняет его в режиме `READ ONLY`
  с ограничением времени и количества строк, поэтому изменить базу
  через такой элемент нельзя.

### Экран «Форма» и рабочее пространство

Каждая форма проекта — это один экран приложения. На холсте экран
показан элементом **«Форма»** с белым фоном; точечная область вокруг —
только рабочее пространство конструктора. В предпросмотре и готовом
приложении показывается **только экран**, без точечного холста и лишних
надписей.

- Корневой элемент «Форма» создаётся автоматически и не удаляется
  и не копируется отдельно от формы.
- Размер экрана задаётся маркером на элементе «Форма» или полями
  «Ширина экрана» / «Высота экрана» в свойствах формы. Все элементы
  внутри масштабируются пропорционально.
- Перетаскивание самого элемента «Форма» двигает экран по рабочему
  пространству; на предпросмотр это не влияет.

### Панель: свободный контейнер

**Панель** — это свободный контейнер, как `Panel` в WinForms. У неё есть
заголовок, внутренние поля, фон и рамка. Панель можно перемещать
и свободно растягивать за маркер размера. При изменении размера все
дочерние элементы и вложенные панели масштабируются и перемещаются
пропорционально.

- Перетащите элемент из палитры прямо в панель или вложите панель
  в панель — ограничений по вложенности нет.
- У каждого дочернего элемента хранятся координаты `x`, `y` и размеры
  `w`, `h` относительно внутренней области родителя.
- Копирование, дублирование и удаление панели захватывают всё её
  содержимое.
- Панель можно выравнивать и растягивать вместе с другими элементами
  того же контейнера.

### Масштабирование нескольких элементов

Выделите несколько элементов (`Ctrl`/`Shift` + клик или рамкой)
и потяните за маркер размера у любого из них — вся группа
масштабируется пропорционально относительно общего прямоугольника.
Если в группе есть панели, их содержимое масштабируется вместе с ними.

### Редактирование на холсте

- **Двойной клик** по тексту или кнопке — быстрое изменение надписи
  прямо на холсте. Enter или клик вне элемента сохраняет, Esc отменяет.
- **Двойной клик** по изображению открывает выбор файла.
- **Ctrl+C / Ctrl+V** копирует и вставляет выделенные элементы
  со смещением. **Ctrl+D** дублирует их.
- **Ctrl+A** выделяет все элементы формы.
- **Рамка выделения** — протяните мышью по пустому месту холста.
- **Ctrl** или **Shift** + клик добавляет элементы к выделению.
- **Delete** удаляет выделенные элементы.
- **Стрелки** двигают выделенные элементы на 1 px,
  **Shift + стрелка** — на шаг сетки.
- **Ctrl+Z** отменяет изменение, **Ctrl+Y** или **Ctrl+Shift+Z**
  повторяет. Те же действия доступны стрелками **↶ / ↷** в верхней панели.

### Выравнивание, магнит и промежутки

- **Магнит** включает примагничивание к сетке, краям и центрам других
  элементов и к центру формы. Во время перетаскивания показываются
  красные направляющие. Если магнит выключен, элементы двигаются свободно.
- Кнопки над холстом выравнивают один элемент по краям формы или группу
  элементов друг относительно друга, а также распределяют элементы
  по горизонтали и вертикали.
- **Отступ** задаёт одинаковый промежуток в пикселях. Кнопки **⇹|**
  и **⇳|** расставляют выделенные элементы с равными промежутками
  по горизонтали или вертикали.
- **Расстояния между элементами** показываются оранжевыми линиями
  с числами, как в Figma. Для выделенной группы видны внутренние
  промежутки по горизонтали и вертикали, для одного элемента —
  ближайшие расстояния до соседей слева, справа, сверху и снизу.
  Значения обновляются прямо во время перетаскивания и изменения
  размера.
- **Шаг сетки**, магнит и показ сетки настраиваются в диалоге «Проект».

### Размеры панелей и подсказки

- Тонкие ползунки между левой панелью, холстом и правой панелью меняют
  их ширину. Ползунки между списком элементов и таблицами, а также
  между списком форм и свойствами меняют высоту этих блоков.
- Ползунок можно перетащить мышью или выделить **Tab** и двигать
  стрелками (**Shift** — крупный шаг). Двойной клик по ползунку
  возвращает размеры по умолчанию.
- Выбранные размеры запоминаются в приложении (локальное хранилище
  встроенного окна) и восстанавливаются при следующем открытии.
- У каждой подсказки есть кнопка **×**. Закрытая подсказка больше
  не показывается; если её текст изменится, она появится снова.

## Таблицы и связи

Вкладка **«Таблицы и связи»** — системная: она всегда находится в одной
полосе с формами и открывается кликом по ней. Вкладка сделана в виде
ER-диаграммы:

- **Карточки таблиц** показывают колонки, типы, первичные и внешние ключи.
  Карточки можно свободно перетаскивать; их положение сохраняется
  в проекте.
- **Связь создаётся кнопкой ↗** у колонки: нажмите её, затем колонку
  в другой таблице. Линии связей рисуются поверх диаграммы.
- **Наведение на связь** подсвечивает связанные таблицы и колонки.
- **«▤ Разложить»** автоматически расставляет карточки, если они
  перекрываются или потерялись.
- **«＋ Таблица»** создаёт таблицу: имя и список колонок с типами,
  первичным ключом, уникальностью, обязательностью и значением
  по умолчанию.
- **«＋ База данных»** создаёт новую базу на том же сервере.
- **Ошибки** (занятое имя, неверный тип, конфликт ключей) показываются
  в диалоге и всплывающим сообщением; связь можно отменить кнопкой
  «Отмена» или клавишей Esc.

Отдельного управления схемами нет: приложение работает со стандартной
схемой `public`. Все изменения сразу выполняются в PostgreSQL. Имена
передаются через `psycopg2.sql.Identifier`, типы проверяются по белому
списку.

## Проекты: сохранение и перенос

- Проект автоматически сохраняется в `projects` после каждого изменения.
- **«Проект» → «Скачать файл»** сохраняет проект в файл
  `Имя.db2ui.json`. Внутри — формат `db2ui.project` версии 2.
- **«Загрузить файл»** читает такой файл и заменяет текущий проект.
- **«Сохранить как…»** создаёт отдельную копию в библиотеке.
- **Библиотека проектов** показывает сохранённые файлы: их можно
  открыть, скачать или удалить.
- **«Новый проект»** создаёт чистый интерфейс, не удаляя старый файл.
- Проект привязан к комбинации `сервер + порт + имя базы`, поэтому
  разные базы не перезаписывают интерфейсы друг друга.
- Старые проекты версии 1 открываются автоматически: недостающие
  настройки форм, сетки и авторизации добавляются при загрузке.

Подробно о том, где лежат файлы, что внутри и как сделать резервную
копию, написано в **[`SAVING_PROJECTS.md`](SAVING_PROJECTS.md)**.

## Авторизация без кода

На вкладке **«Авторизация»** можно включить вход в предпросмотр:

1. Нажмите **«Создать таблицу пользователей»**. Мастер создаст таблицу
   (по умолчанию `app_users`) с колонками логина, пароля и роли
   и добавит администратора.
2. Выберите таблицу и колонки логина, пароля и роли.
3. Укажите, как хранится пароль: обычный текст или хеш SHA-256.
4. Включите переключатель «Требовать вход перед открытием интерфейса».
5. При необходимости включите **«Разрешить регистрацию новых
   пользователей»**.

Пользователей можно добавлять, удалять и менять им пароль прямо
на этой вкладке. В предпросмотре появляется экран входа с проверкой
логина и пароля, имя пользователя, кнопка «Выйти» и, если регистрация
разрешена, ссылка «Зарегистрироваться». Регистрация проверяет:

- логин — от 3 до 64 символов, буквы, цифры и `. _ @ -`;
- пароль — от 4 до 128 символов;
- повтор пароля должен совпадать;
- занятый логин не создаётся повторно.

Кнопка на форме с действием «Войти» или «Зарегистрировать» открывает
соответствующий экран, а с действием «Выйти из учётной записи» —
завершает сеанс.

### Переход после входа по роли

Если после входа разным ролям нужны разные экраны, настройте это
в свойствах кнопки с действием **«Войти (логин и пароль)»** или
**«Зарегистрировать»**:

1. Выберите кнопку входа и откройте её свойства.
2. В блоке **«После успешного входа»** укажите форму по умолчанию —
   она откроется, если роль не совпала ни с одной строкой.
3. Нажмите **«+ роль»** и выберите роль из списка. Список собирается
   по пользователям на вкладке **«Авторизация»**; кнопка **↻** рядом
   обновляет его из таблицы. Роль сравнивается без учёта регистра,
   поэтому `Admin`, `admin` и ` admin ` считаются одной ролью.
4. Выберите форму для этой роли. При необходимости добавьте несколько
   ролей. Сработает первая подходящая строка.

Порядок выбора формы после успешного входа:

1. форма из строки с совпавшей ролью;
2. форма по умолчанию из свойств кнопки;
3. стартовая форма проекта.

Настройки хранятся в проекте вместе с кнопкой, поэтому работают
и после сохранения, и в готовом приложении.

> Авторизация предназначена для учебных интерфейсов. Она ограничивает
> вход в предпросмотр, но не заменяет полноценную систему прав:
> подключение к PostgreSQL всё равно выполняется от имени пользователя,
> указанного при подключении.

## Функции, процедуры и триггеры

Вкладка **«Функции и триггеры»** находится в верхней полосе рядом
с «Конструктором» и «Авторизацией». На ней можно создавать серверные
объекты PostgreSQL без переключения в psql:

- **Список объектов** сгруппирован по видам: функции, процедуры
  и триггеры. Для каждого объекта показаны схема, имя, аргументы,
  результат, таблица и события триггера.
- **Шаблоны** «Функция», «Процедура», «Триггер» и «Триггерная функция»
  подставляют готовый каркас с `CREATE OR REPLACE`. Перед заменой
  уже введённого кода приложение спросит подтверждение.
- **Клик по объекту** загружает его `CREATE`-определение
  (`pg_get_functiondef` / `pg_get_triggerdef`) в редактор. Оттуда его
  можно исправить и выполнить повторно.
- **«Выполнить»** (или `Ctrl+Enter` в редакторе) выполняет код сразу
  в текущей базе. За один раз разрешён ровно один оператор:
  `CREATE FUNCTION`, `CREATE PROCEDURE` или `CREATE TRIGGER`.
  Допускается `OR REPLACE`, `CREATE CONSTRAINT TRIGGER` и тела
  в dollar-quoting (`$$ ... $$`).
- **«Удалить»** удаляет выбранный объект по его OID. Имена берутся
  из системного каталога, поэтому удаление не зависит от текста
  в редакторе.

Триггер выполняется функцией с типом результата `trigger`: сначала
создайте такую функцию, затем триггер с `EXECUTE FUNCTION`.
Если функция используется триггером, PostgreSQL не позволит удалить
её до удаления триггера — приложение покажет эту ошибку.

> Код выполняется от имени пользователя, указанного при подключении.
> Ошибки синтаксиса, занятые имена и нехватка прав показываются
> в красном блоке над редактором.

## Экспорт приложения в один .exe

Кнопка **⇩ Скачать** в верхней панели, в предпросмотре или
**☰ Проект → ⇩ Скачать .exe** собирает один файл `<название>.exe`.

Это полноценное приложение, а не снимок: оно подключается к вашей базе
PostgreSQL и читает/записывает живые данные. Внутри файла уже есть:

- встроенный Python 3.12;
- Flask и psycopg2;
- локальный сервер и интерфейс приложения;
- формы, элементы и настройки проекта;
- заготовка подключения без пароля.

### Что нужно на новом компьютере

1. Windows 10 или 11 (64-бит).
2. Доступ к серверу PostgreSQL, где лежат данные приложения.

Python, Flask и другие зависимости устанавливать не нужно.

### Как открыть

1. Скопируйте `.exe` на компьютер пользователя.
2. Дважды щёлкните по файлу.
3. При первом запуске введите пароль PostgreSQL — сервер, база
   и пользователь уже вписаны. Пароль **не хранится в файле**.
4. Откроется браузер с приложением. Дальше оно подключается
   автоматически.

Приложение занимает `http://127.0.0.1:8765/`; если порт занят, берётся
следующий свободный. При первом запуске файл распаковывает встроенный
Python в `%LOCALAPPDATA%\DB2UI Player`, поэтому старт может занять
несколько секунд. Остановка — закрыть окно с логами или `Ctrl+C`.

### Обновление приложения

После изменений в конструкторе нажмите **⇩ Скачать** заново: новый `.exe`
заменит старый. Формы и настройки хранятся внутри файла, а записи
таблиц — в PostgreSQL.

## Подключение и безопасность

Параметры подключения вводятся в самой программе и хранятся только
в памяти серверного процесса. В cookie встроенного окна лежит лишь
случайный идентификатор сессии. **Пароль PostgreSQL не записывается
в файлы проекта.**

Файл `.env` нужен только для предзаполнения формы подключения:

```ini
PGHOST=localhost
PGPORT=5432
PGDATABASE=postgres
PGUSER=postgres
PGPASSWORD=postgres
```

| Переменная | Что означает | По умолчанию |
|---|---|---|
| `PGHOST` | адрес сервера PostgreSQL | `localhost` |
| `PGPORT` | порт | `5432` |
| `PGDATABASE` | имя базы данных | `postgres` |
| `PGUSER` | имя пользователя | `postgres` |
| `PGPASSWORD` | пароль (только для предзаполнения) | `postgres` |

Дополнительные настройки приложения:

| Переменная | Что означает | По умолчанию |
|---|---|---|
| `DB2UI_PORT` | порт локального сервера приложения | `8501` |
| `DB2UI_NO_BROWSER` | `1` — не открывать браузер (только режим `app.py`) | не задано |
| `DB2UI_SECRET` | секрет Flask для cookie сессии | хранится в `secret.key` |
| `DB2UI_DATA_DIR` | папка для проектов и настроек | `%LOCALAPPDATA%\DB2UI Studio` (в exe) |

Если в пароле есть пробелы, `#` или другие спецсимволы, заключите его
в кавычки: `PGPASSWORD="мой пароль"`.

## Где хранятся проекты

При запуске из исходников собранные интерфейсы лежат в папке `projects`
рядом с `app.py`. В установленной десктопной версии — в
`%LOCALAPPDATA%\DB2UI Studio\projects` (эта папка не удаляется при
удалении программы). Путь можно переопределить переменной окружения
`DB2UI_DATA_DIR`.

Имя файла содержит базу, короткий хеш подключения и название проекта,
например `my_db_3cc7d37e2c__Мой_проект.json`. Проект привязан
к комбинации `сервер + порт + имя базы`, поэтому разные базы не
перезаписывают интерфейсы друг друга.

В JSON-файле хранятся формы, элементы, макет, настройки авторизации
и расположение карточек на ER-диаграмме. **Данные таблиц и пароли
пользователей в проект не попадают.** Изображения, добавленные файлом,
встраиваются в проект как `data URL`.

Файлы проектов можно копировать и переносить. Пароль PostgreSQL
в них не хранится: он лежит отдельно в `%LOCALAPPDATA%\DB2UI Studio\credentials.json`
в зашифрованном виде (Windows DPAPI) и привязан к учётной записи Windows.
Поэтому на другом компьютере пароль нужно ввести один раз заново.

## Если что-то не работает

**`password authentication failed for user "postgres"`**  
Неверный пароль. Введите правильный в форме подключения.

**`database "..." does not exist`**  
Указана несуществующая база. Создайте её кнопкой «＋ База данных»
на вкладке «Таблицы и связи» или в psql:
`CREATE DATABASE db2ui;` — либо укажите существующую.

**`connection refused` / `could not connect to server`**  
PostgreSQL не запущен либо неверны сервер или порт. Проверьте службу
PostgreSQL в Windows и раздел «Дополнительно» → «Порт».

**В списке нет нужных таблиц**  
Показываются только пользовательские таблицы, системные скрыты.
Нажмите **«↻ Таблицы»** после создания таблицы.

**У таблицы не работают изменение и удаление**  
Для `UPDATE` и `DELETE` нужен первичный ключ. Добавлять записи можно
и без него. Создайте первичный ключ на вкладке «Таблицы и связи»
(при создании таблицы или добавьте колонку с PK) либо в psql:
`ALTER TABLE my_table ADD PRIMARY KEY (id);`

**Связь не создаётся**  
Проверьте, что обе колонки имеют совместимый тип и что у целевой
колонки есть уникальный индекс или первичный ключ. Текст ошибки
PostgreSQL показывается в диалоге и во всплывающем сообщении.

**Изменения в psql не видны сразу**  
Данные кешируются на несколько секунд. Нажмите «↻» в заголовке таблицы
в предпросмотре или «↻ Таблицы» в редакторе.

**После перезапуска приложения снова нужен пароль**  
Обычно нет: выбранный проект открывается сразу, если пароль уже
сохранялся. Пароль хранится в зашифрованном виде (Windows DPAPI) и только
для вашей учётной записи Windows — файлы проектов его не содержат.
Если проект открылся с запросом пароля, введите его один раз: дальше
он будет открываться сразу. Проект интерфейса останется в `projects`.

**Не работает регистрация в предпросмотре**  
Убедитесь, что на вкладке «Авторизация» включён переключатель
«Разрешить регистрацию новых пользователей» и выбрана таблица
пользователей с колонками логина и пароля.

## Важно

Это **учебный инструмент**, а не production-приложение. Авторизация
на вкладке «Авторизация» ограничивает вход в предпросмотр, но не
разграничивает права доступа к базе: приложение подключается
к PostgreSQL от имени указанного пользователя, поэтому его права
полностью действуют и в интерфейсе. Не используйте инструмент для
боевых баз без отдельного пользователя с ограниченными правами.
