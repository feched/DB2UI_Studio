# Как DB2UI Studio сохраняет проекты

Этот файл объясняет, где физически лежат ваши интерфейсы, что попадает
в файл проекта и как перенести работу на другой компьютер.

## Коротко

* Интерфейс (формы, кнопки, таблицы, связи, настройки) хранится **локально**
  на том компьютере, где запущен `app.py`.
* Файлы лежат в папке **`F:\DB2UI\projects`** и имеют расширение `.json`.
* Данные таблиц (строки) хранятся **в PostgreSQL**, а не в JSON-файле.
* Изображения, добавленные через свойства элемента, встраиваются прямо
  в проект как `data URL`, поэтому проект остаётся переносимым.
* Автономный HTML-предпросмотр — это отдельный файл-снимок. Он работает
  без Python, PostgreSQL и интернета.

## Где именно лежит проект

Для каждого подключения создаётся один файл:

```text
F:\DB2UI\projects\<имя_базы>_<хеш>.json
```

Хеш считается от пары «сервер + порт + имя базы». Поэтому:

* одна и та же база на одном и том же сервере всегда открывает свой файл;
* разные базы или разные серверы получают разные файлы;
* переименование проекта через «Сохранить как» создаёт дополнительный файл
  вида `<имя_базы>_<хеш>__<название>.json`, не удаляя старый.

Текущий файл можно увидеть в диалоге **☰ Проект → Библиотека проектов**.

## Когда происходит сохранение

1. При любом изменении формы, элемента или настройки интерфейс помечает
   проект как изменённый и показывает статус **«Сохранение…»**.
2. Через полсекунды проект автоматически отправляется на локальный сервер
   DB2UI и записывается в JSON-файл.
3. После успешной записи статус меняется на **«Сохранено»**.
4. Если запись не удалась, появится красное сообщение, а в верхней панели
   будет **«Не сохранено»**. В этом случае проверьте, что папка `projects`
   доступна для записи и на диске есть место.

Кнопка **Ctrl+S** сохраняет немедленно.

Перед закрытием вкладки браузер предупредит, если остались несохранённые
изменения.

## Что находится внутри JSON-файла

Файл проекта — обычный текст в кодировке UTF-8. В нём есть:

* `name` — название проекта;
* `start_form` — стартовая форма;
* `forms` — все формы-экраны, их размеры, цвет и элементы;
* `elements` — плоский список элементов формы. У каждого есть `id`,
  `type`, `name`, `x`, `y`, `w`, `h` и `parentId`;
* `parentId` — родительский контейнер: корневой элемент `form` (экран)
  или `panel`. Пустой `parentId` у корневого элемента «Форма»;
* `x`, `y`, `w`, `h` — координаты и размеры в пикселях относительно
  внутренней области родителя (для корневого элемента — относительно
  рабочего пространства);
* `panel` — оформление и внутренние поля панели (`title`, `padding`,
  `background`, `border`);
* `query` — текст SQL-запроса (сами результаты запроса в проект не сохраняются);
* `auth` — настройки входа и регистрации;
* `settings` — шаг сетки, магнит, показ сетки;
* `db_layout` — координаты таблиц на ER-диаграмме;
* `meta` — имя базы, сервер и порт (только для справки).

В каждой форме ровно один корневой элемент с `type: "form"` и пустым
`parentId`. Его ширина и высота совпадают с `width` и `height` формы.
Остальные элементы ссылаются на него или на панели через `parentId`.

Проекты старого формата с сеткой (`layout.mode: "grid"`) и ячейками
`cell` открываются автоматически: конструктор создаёт корневой экран,
переводит ячейки в пиксельные координаты и сохраняет проект уже
в новом виде. Отдельная миграция или Alembic не нужны.

Данные таблиц и пароли пользователей в JSON **не попадают**. Пароли
пользователей приложения лежат в таблице пользователей PostgreSQL
(в виде обычного текста или SHA-256 — зависит от настроек авторизации).

## Библиотека проектов и резервные копии

В диалоге **☰ Проект** доступны:

* **Скачать файл** — получить копию текущего проекта в формате
  `.db2ui.json`;
* **Загрузить файл** — заменить текущий проект ранее сохранённой копией;
* **Сохранить как** — создать новый файл проекта в папке `projects`;
* **Библиотека** — открыть, скачать или удалить любой проект из папки.

Самый простой бэкап: скопируйте всю папку

```text
F:\DB2UI\projects
```

на флешку или в облако. Этого достаточно, чтобы сохранить интерфейсы.
Если нужны и данные, сделайте дамп PostgreSQL:

```powershell
pg_dump -h localhost -p 5432 -U postgres -d имя_базы -F c -f backup.dump
```

Восстановление:

```powershell
pg_restore -h localhost -p 5432 -U postgres -d имя_базы backup.dump
```

## Изображения

Изображение можно добавить двумя способами:

1. указать ссылку `https://…` в свойстве **«Ссылка на изображение»**;
2. выбрать файл с компьютера (до 2 МБ) — он будет встроен в проект.

Во втором случае файл проекта увеличивается на размер картинки. Это
нормально: так проект остаётся одним переносимым файлом. Если изображений
много и они большие, удобнее хранить их на сервере и указывать ссылки.

## Автономный HTML-предпросмотр

Кнопка **⇩ HTML** в предпросмотре или **☰ Проект → ⇩ HTML-предпросмотр**
создаёт файл `<название>.preview.html`.

Внутри уже есть:

* все формы и элементы;
* стили;
* снимок первых 100 строк каждой таблицы;
* настройки входа и список пользователей для локальной проверки.

Такой файл можно открыть двойным кликом на любом компьютере с браузером.
Он **не подключается к PostgreSQL**:

* таблицы показываются только для чтения;
* кнопки «Добавить запись» не сохраняют данные;
* регистрация в автономном файле действует до закрытия страницы;
* изменения интерфейса в HTML-файл не записываются.

Если нужно обновить данные в автономном файле, экспортируйте его заново.

## Новый проект

На экране подключения кнопка **«＋ Новый проект»** подключается к базе
и сразу создаёт чистый интерфейс с одной пустой формой. Старый файл
проекта при этом не удаляется: он остаётся в библиотеке.

Кнопка **«Подключить»** открывает последний сохранённый проект этой базы.

## Чего не нужно делать

* Не редактируйте JSON вручную — легко нарушить структуру.
* Не удаляйте папку `projects` во время работы приложения.
* Не переименовывайте файлы проекта в проводнике: открывайте их через
  библиотеку или загружайте через «Загрузить файл».
* Не рассчитывайте, что проект сохраняется в браузере. Он сохраняется
  на диск рядом с `app.py`, в папке `projects`.
